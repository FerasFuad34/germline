# 🎓 دليل صياغة مشروع التخرج
## من الجينوم المناعي إلى عنوان يقبله المشرف ويستطيع طالب واحد تنفيذه

*مرجع عملي — أكتوبر 2026*

---

## 1) القاعدة الذهبية قبل أي عنوان

> **العنوان ليس وصفاً لحلمك… بل وعدٌ تنفيذي.**
> المشرف يقرأ العنوان ويسأل ثلاثة أسئلة في ثوانٍ: **ماذا؟ كيف؟ على ماذا؟** —
> إذا لم يجدها، سيرفض أو يعيدك لتضيّق النطاق.

هذا هو خطأ الطالب الأول: عنوان مثل «نظام أمان وطني بالذكاء الاصطناعي» يُرفض لأنه بلا نطاق.
والعنوان المدفون أيضاً يُرفض. المطلوب: **طموح في السؤال، تواضع في النطاق.**

---

## 2) صيغة الصياغة — القالب الرباعي

```
[فعل المساهمة]  +  [بعُقدة الاتصال]  +  [كيفية التنفيذ]  +  [النطاق المحدد]
```

| البند | في مشروعك (الجينوم المناعي) | لازم يكون في العنوان |
|---|---|---|
| **فعل المساهمة** | قياس / تصميم / بناء / التحقق | التحقق من *ماذا* تحديداً |
| **عُقدة الاتصال** | وراثة الحمايات الأمنية عبر الأجيال | الرابط الفكري (وليس الوصف العام) |
| **كيفية التنفيذ** | اختبارات تنفيذية مولّدة من CVE + تتبّع سلالة + بوابة CI | الآلية بإيجاز |
| **النطاقالمحدد** | إعادة كتابة C→Rust بالـAI على مكتبات محددة (giflib/zlib) | عدد/نوع/حالة دراسية |

**مثال مُطبَّق (العنوان المرشح الأول):**
> «التحقق من **وراثة الحمايات الأمنية** في **إعادة الكتابة بالذكاء الاصطناعي** عبر **اختبارات مولّدة من ثغرات CVE** — دراسة حالة على **تحويل مكتبات C إلى Rust**»

## 3) قوالب جاهزة (اختر حسب طبيعة مشروعك)

| القالب | الشكل | يصلح لـ |
|---|---|---|
| **قالب القياس** 📏 | «قياس X في Y: دراسة تجريبية على Z» | أقوى قالب أكاديمياً — يفتح باب النشر |
| **قالب البناء + التقييم** 🔧 | «تصميم وبناء أداة X لتقييم Y في Z» | مشاريع هندسية — ينتج منتجاً ملموساً |
| **قالب السؤال** ❓ | «هل تحافظ Y على X؟ تحليل تجريبي وتطبيق عملي على Z» | يجذب انتباه اللجنة فوراً |
| **قالب الثنائي (نقطتان)** ⚖️ | «المفهوم الكبير: التفصيل التنفيذي» | يجمع الطموح + النطاق معاً |

⚠️ القوالب الأربعة قابلة للدمج: «قياس + بناء» هو الأفضل لمشروع تخرج ممتاز.

## 4) مصفوفة العناوين المقترحة (مصنّفة بحسب حجم المشروع)

### أ) للحجم الصغير — فصل واحد / مشروع بكالوريوس مركّز

**A1 — قياسي بحت (الأسهل تنفيذاً):**
> **عربي:** «النسيان المناعي للبرمجيات: قياس فقدان الحمايات التاريخية في الترجمة الآلية من C إلى Rust — دراسة حالة على مكتبتين حرجتين»
> **English:** *Software Immune Amnesia: Measuring the Loss of Historical Protections in AI-Assisted C-to-Rust Translation — A Case Study of Two Critical Libraries*

**A2 — خط الأنابيب:**
> **عربي:** «من ثغرة CVE إلى اختبار انحدار تنفيذي: بناء خط أنابيب آلي لاستخراج "الأمصال" الأمنية من تاريخ الثغرات»
> **English:** *From CVE to Executable Regression Antibody: An Automated Pipeline for Extracting Security Tests from Vulnerability History*

### ب) للحجم المتوسط — سنة كاملة / مشروع ممتاز مع مرتبة الشرف

**B1 — قياس + بناء (⭐ الأوصى به):**
> **عربي:** «النسيان المناعي في إعادة الكتابة بالذكاء الاصطناعي: قياس وراثة الحمايات الأمنية وتصميم بوابة تحقق في خطوط CI/CD»
> **English:** *Immune Amnesia in AI-Assisted Code Rewrites: Measuring the Inheritance of Security Protections and a CI/CD Verification Gate*

**B2 — سؤالي:**
> **عربي:** «هل ترث النسخة المُعاد كتابتها ضمانات نسختها الأصلية؟ تحليل تجريبي للوراثة الأمنية عبر الأجيال وتطبيق بوابة تحقق»
> **English:** *Do Rewritten Codebases Inherit Their Ancestors' Security Guarantees? An Empirical Analysis of Cross-Generation Inheritance and a Verification Gate*

**B3 — حالة دراسية مركزة (ممتاز للعرض الشفهي):**
> **عربي:** «الذاكرة المناعية لمكتبة giflib: ماذا بقي من حمايات النسخة الأصلية بعد إعادة كتابتها بالذكاء الاصطناعي؟»
> **English:** *The Immune Memory of giflib: What Survives of the Original Protections After an AI-Assisted Rewrite?*

### ج) للحجم الطموح — ماجستير أو ورقة مؤتمر

**C1 — النظري:**
> **عربي:** «نحو إطار للوراثة المناعية في الأنظمة البرمجية: نمذجة انتقال الضمانات الأمنية عبر إعادة الكتابة والترجمة الآلية»
> **English:** *Toward an Immune-Inheritance Framework for Software Systems: Modeling the Transfer of Security Guarantees Across Automated Rewrites and Translations*

---

## 5) العنوان الموصى به لك + النسخة المختصرة

### الترشيح النهائي (B1 — قياس + بناء):

> ### «النسيان المناعي في إعادة الكتابة بالذكاء الاصطناعي: قياس وراثة الحمايات الأمنية وتصميم بوابة تحقق في خطوط CI/CD»
> *Immune Amnesia in AI-Assisted Code Rewrites: Measuring the Inheritance of Security Protections and a CI/CD Verification Gate*

**لماذا هذا العنوان ذكي؟ (5 أسباب تجعل المشرف يوافق):**
1. **يحتوي فعلاً قابلاً للقياس** («قياس وراثة») — ليس وصفاً إنشائياً.
2. **عبارة مبتكرة غير موصومة** («النسيان المناعي» = Immune Amnesia) — مفهوم جديد تعرّفه أنت، وغير مستهلك مثل «جهاز مناعة رقمي» (المصطلح الذي قَتل فكرتك الأولى).
3. **نطاق واضح ومغلق** (إعادات كتابة بالـAI + CI/CD) — يمكن لطالب واحد إنجازه.
4. **جزء بناء** (البوابة) — فمخرجاته منتج + ورقة، ينفعانك مهنياً.
5. **آمن بحثياً:** لا يتضمن توزيع ترقيعات ولا انتحال صلاحيات — لا يفتح أسئلة قانونية.

### النسخة المختصرة (للاستمارة الجامعية — غالباً 15 كلمة كحد أقصى):
> «قياس الوراثة الأمنية وتصميم بوابة تحقق لسلامة إعادة كتابة الكود بالذكاء الاصطناعي»
> *Measuring Security Inheritance in AI-Assisted Code Rewrites and a Verification Gate*

### إذا طُلِب منك عنوان عربي فقط بأسلوب تقليدي:
> «قياس فقدان الحمايات الأمنية في الترجمة الآلية للكود وتطوير أداة تحقق للجودة الأمنية»

## 6) الفخّان الذين يهدمان أي عنوان (اسمعها مني الآن، لا من اللجنة)

| ❌ لا تقترب من | السبب |
|---|---|
| «نظام مناعة عالمي» / «دفاع جماعي ذاتي» | مصطلح Gartner المُستهلك + فكرتك الأولى التي هدمناها |
| «توزيع تلقائي للترقيعات» | كارثة أخلاقية وقانونية موثقة (Welchia)، ومفتاح رفض فوري |
| «بلوكتشين» في العنوان دون حاجة فعلية | اللجان صارت متحسسة منه |
| «حماية الإنترنت من جميع الهجمات» | ادعاء استحالي = رفض مباشر |
| عناوين بلا قسم «النطاق» | «الذكاء الاصطناعي في الأمن السيبراني» — بلا مشكلة محددة |

**وبالمقابل — هذه هي الكلمات المفتاحية الآمنة والقوية:**
`قياس` · `تحقق` · `وراثة/انتقال الحمايات` · `دراسة تجريبية` · `دراسة حالة` · `خط أنابيب/بوابة` · `اعتماد + توقيع` · `إعادات كتابة بالذكاء الاصطناعي` · `أمن سلسلة توريد البرمجيات`

## 7) ما هو الموجود أكاديمياً — وما الفراغ (لن يسألك المشرف أخطر من هذا)

**اعرف هذه الأوراق قبل أن يسألك أحد عنها** — والفراغ بعدها سيصبح سلاحك:

| الموجود مسبقاً | ماذا يفعل | القريب منك |
|---|---|---|
| دراسة إعادة إدخال الثغرات — ImageMagick (يناير 2026) | تتبّع 76 ثغرة أُعيد إدخالها بالـSZZ في نفس المشروع | تقيس «إعادة الإدخال» داخل نفس المستودع — **لا تعبر بين الأجيال ولا اللغات** |
| An Exploratory Study on Regression Vulnerabilities (ESEM 2022) | عائلة أبحاث «ثغرات الانحدار» | نفس الملاحظة: زمني داخل مشروع واحد |
| **Vul4J** (توهانوفر) | 79 ثغرة Java قابلة للتكرار مع اختبارات إثبات ثغرة (PoV tests) | أرضية رخيصة لجزء «الأمصال» — استخدمها بدل البناء من الصفر |
| **ARVO** (موسّع مستمر) | قاعدة ثغرات C/C++ قابلة للتكرار مأخوذة من OSS-Fuzz (Docker) | أرضية مثالية لنطاق C→Rust |
| FaultLine (2025) | توليد PoV آلي بالـLLM لعينات Java | قريب جداً من «مولّد الأمصال» — اقتبسها كحدود، وفراغك بعدها |
| OSS-Fuzz | يحتفظ باختبارات المُكرِّر (reproducers) ويحسب نطاقات الانحدار | مناعة داخلية لكل مشروع — غير محمولة ولا وراثية عبر الأجيال |

**🎯 الفراغ المحدد الذي سيميّزك (اذكره بهذه الصيغة الحرفية في المقترح):**

> *"بينما درست الأبحاث السابقة إعادة إدخال الثغرات ضمن تاريخ مستودع واحد، وبينما توفر قواعد بيانات مثل Vul4J وARVO اختبارات مُكرِّرة محلية، لا يوجد — حسب علمنا — أي عمل يقيس منهجياً انتقال الضمانات الأمنية (المناعة الوراثية) عبر **إعادات الكتابة والترجمات الآلية بين اللغات**، ولا أي أداة تفرض ذلك بوابةً موقّعة في خطوط CI/CD."*

هذه الجملة وحدها = نص مساهمتك العلمية. احفظها.

## 8) أسئلة اللجنة المتوقعة — وإجاباتك الجاهزة

| السؤال | إجابتك (خُذ هذه حرفياً وجوّهها) |
|---|---|
| «ما الجديد مقابل OSS-Fuzz وVul4J؟» | تلك أدوات **محلية وضمن مستودع واحد**؛ نحن نقيس **العبور بين جيل وجيل ولغة ولغة** في إعادات كتابة الـAI، وننتج **دليلاً موقّعاً محمولاً** |
| «هل ستُعيد كتابة مكتبة بنفسك؟» | لا — النطاق التجريبي يستخدم إعادات كتابة قائمة أو تجربة مصغّرة على وحدة محددة؛ **العلم في القياس والتحقق لا في إعادة الكتابة** |
| «كيف تمنع اختبارات كاذبة؟» | معيار القبول الصارم: **يفشل على النسخة المصابة وينجح على المُصلَحة** — وإلا يُرفض المصل آلياً |
| «ألا تعدّ هذا اختبارات انحدار عادية؟» | اختبارات الانحدار **تحمي جيلاً واحداً وتُنسى**؛ مفهومنا يجعلها **تراثاً وراثياً موقّعاً يسافر مع السلالة** عبر اللغات |
| «جودة الـLLM؟» | المولّد ليس سلطة: التحقق تجريبي (تشغيل فعلي) + مراجعة بشرية + قياس معدل الإيجابيات الكاذبة ونشره |
| «لماذا giflib/zlib؟» | صغيرة (آلاف الأسطر)، تاريخ CVE غني، تُعالج مدخلات غير موثوقة، وهناك سابقة إعادة كتابة بالـAI منشورة رسمياً |

## 9) الجدول الزمني المصغّر (سنة — قابلة للضغط إلى فصلين)

```
 المرحلة 1 (شهر 1–2):    مسح أدبيات + اختيار المكتبات (2–3) + جمع سلالات CVE + استخدام ARVO/Vul4J
 المرحلة 2 (شهر 3–5):    بناء مستخرج الأمصال + معيار القبول الآلي + قياس الدقة (ملف البيانات يُنشر)
 المرحلة 3 (شهر 6–8):    بناء بوابة التحقق + تشغيل القياس على إعادات الكتابة → "هل حدث نسيان مناعي؟"
 المرحلة 4 (شهر 9–10):   التحليل + كتابة الأداة العامة (open source) + ورقة أولية
 المرحلة 5 (شهر 11–12):  التقرير النهائي + العرض + (اختياري) تقديم ورقة لمؤتمر/مجلة
```

**المخرجات القابلة للتسليم (5 قطع اضمنها في المقترح):**
1. قاعدة بيانات أمصال موثّقة (Dataset) لمكتبات مختارة — قابلة للنشر العام.
2. أداة مفتوحة المصدر: مولّد الأمصال + بوابة التناظر.
3. نتائج قياسية: «هل فقدت إعادات كتابة الـAI مناعة أسلافها؟ وكم؟».
4. تقرير التخرج + عرض.
5. (نجمة إضافية) ورقة بحثية قابلة للتقديم.

## 10) خلاصة سريعة — خمس قواعد فعلية

1. **العنوان = وعد لا حلم:** افعل + كيف + على أي شيء، بثلاث دقائق مفهومة.
2. **اختر «النسيان المناعي» لا «الجهاز المناعي»:** مصطلحك الجديد يحميك من مقارنات سلبية بتاريخ الشائعات.
3. **اذكر النطاق دائماً:** نوع إعادات الكتابة + عدد المكتبات + الأدوات (ARVO/Vul4J/giflib).
4. **ادمج القياس مع البناء:** تقاس + تبني → تخرج متميز وورقة مؤتمر قابلة للنشر.
5. **احفظ جملة الفراغ البحثي** من القسم 7 حرفياً: هي جواز مرورك أمام أي لجنة.
